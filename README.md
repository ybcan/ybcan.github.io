# 战略工作台

个人工作台：https://ybcan.github.io/ · 版本 0.5.1 · 作者 [ybcan](https://github.com/ybcan) · 更新 2026-11-16

以长期目标组织学习、实践项目与研究，保留学习归档、完成历史、随手记、待办和实验工具。学习讨论继续在 ChatGPT 中进行，工作台负责组织与跟踪。

## 数据保存与恢复

浏览器的 IndexedDB 保存工作副本；独立目录中的 JSON 文件提供浏览器之外的恢复来源。首次使用新版会迁移已有 localStorage v2/v1 记录，保留原始键和已有完成状态。

桌面 Chrome / Edge 在「数据与备份 → 独立文件备份」中选择本机目录或同步盘目录：

- 新目录立即保存一份；之后在页面打开期间合并快速连续编辑，并自动追加版本文件。成功关闭文件后才显示备份成功，不覆盖或自动删除旧文件。
- 若目录中已有版本，先选择恢复旧版本，或「保留当前并立即备份」。重选目录本身不会把历史备份替换成示例数据。
- 目录权限失效会提示重新连接。浏览器工作副本保存成功、文件写入失败会分别显示，不把二者混为一谈。
- 重新打开页面时只检查权限。清除浏览器数据后，需要重新选择原目录，再从版本列表选择并确认恢复。
- 恢复前尝试保留当前版本；失败时可取消并手工导出。确认期间若其他标签页改动工作区，恢复会停止，要求重新确认。

手机及不支持目录 API 的浏览器保留手工「导出工作区／恢复备份」。同步盘仅同步备份文件，工作台不会自动合并多设备改动；关闭网页后不会继续写文件。个人数据不会自动上传到仓库或第三方服务。

单个快照或归档包上限为 **32 MiB（UTF-8）**，超限拒绝写入而不裁剪。工作副本无法保存时，本页普通编辑仍可手工导出；导入或恢复写入失败时不会替换现有工作区。原始异常数据保留下载入口。

## 功能与对象关系

**目标 → 项目 → 任务**。项目承接学习、实践和研究；任务是唯一的可执行动作。计划按时间、优先级展示这些任务；待办展示未完成正式任务。词汇定义见 [CONTEXT.md](CONTEXT.md)。

- 新建项目默认只显示项目名称、关联目标和预期成果，仅名称必填；其余配置在“更多设置”中，已有项目编辑保留完整字段。
- 项目详情、待办与计划视图使用同一任务，完成状态同步；项目进度由正式任务计算。
- 任务支持主归属项目、安排日期、截止日期和优先级；临时任务可暂未归属。AI 候选任务先确认，采纳不会自动完成或开始执行。
- 项目步骤首次读取时转为任务，保留完成状态、原步骤标识及来源。稳定迁移索引防止重复生成；删除过的迁移任务不会因刷新重新出现。
- 旧计划保留为方案资料；明确标注行动的内容转为任务。路线建议、方法、想法放入“积累与归档 → 方案与知识资料”；含义不明确的原文保留，可确认后转为任务或阶段里程碑。
- 保留旧计划的原始状态供历史追溯，其状态不再构成独立执行看板。旧 `plans`、`itemIds` 字段兼容导入，不代表新执行层级。
- 新备份格式为 v3，继续读取 v1/v2；个人浏览器中的数据在本地迁移，无需重新导入。备份成功之前保留原有存储，异常原文可下载。
- 目标树、多目标引用、学习问答及点评、完成历史、搜索和归档分页继续可用。
- 目标、项目、任务、方案资料与归档支持编辑删除；删除前确认，保留其他内容并解除关联，写入失败保留原数据。
- 随手记位于实验空间，常用网站、专注计时和工具继续保留。

## 开发与检查

运行时使用原生 JavaScript 模块，不需要编译。浏览器通过 HTML import map 加载统一版本，Node/类型检查通过包 imports 解析同一套模块。

```sh
npm ci
npm test
npm run typecheck
python3 -m pip install playwright==1.62.0
python3 -m playwright install chromium
npm run test:browser
python3 -m http.server 8000 --bind 127.0.0.1 --directory docs
```

浏览器测试使用隔离上下文和合成数据，不访问个人浏览器工作区。`fake-indexeddb`、TypeScript 和 Playwright 只用于开发与验证。

主要职责：`storage.mjs` 管理事务工作副本；`file-backups.mjs` 管理版本文件和权限；`record-editor.mjs`、`strategy-editor.mjs` 管理编辑；`update-preview.mjs` 管理导入预览；`workspace-views.mjs` 与 `strategy-ui.mjs` 管理列表视图；`tools.mjs` 管理计时和工具；`types.d.ts` 定义关键数据契约。

## 发布与旧博客

`.github/workflows/workbench.yml` 先运行数据、类型和浏览器检查，通过后才部署 `/docs`。仓库 Settings → Pages → Source **需要设置为 GitHub Actions**；如果仍是旧的分支发布，旧发布器不受这个测试门禁控制。

旧博客保留在 `docs/blog.html`、`docs/posts/` 等路径。旧 Hugo 的输出目录改为 `legacy-blog-build/`，重新运行 Hugo 不会覆盖工作台首页；如需更新博客，先在独立目录构建，再人工核对要发布的文件。
